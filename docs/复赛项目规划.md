# 知衡 · 复赛项目规划

复赛只交视频，评委是华为业务人员。目标从"功能完整"转向：**店员愿意用、发出去不重样、数据不出错**。

## 一、要解决的三个问题

| 企业痛点 | 根因判断 | 我们的解法 |
| --- | --- | --- |
| 店员没时间、敷衍、文笔差 | 写推文是额外负担，工具门槛高 | **店员快发模式**：手机打开，选型号 + 一句真实见闻，秒出三平台成稿 |
| 内容千篇一律、AI 味重 | 几千家店输入完全相同，只靠温度换措辞 | **门店真实瞬间做切入点**；句库组合 + 去重；去 AI 味规则 |
| 新品幻觉、过度承诺 | 同一个模型同时负责"记事实"和"写好看" | **事实层与表达层分离**；数字由程序填入，模型和模板都改不了 |

## 二、产品形态：三档模式，共用一套已核验事实

1. **快发模式（新增，默认入口，不调用模型）**
   - 输入：型号、目标人群、一句门店真实见闻（选填但强烈引导）。门店档案一次填写后自动带入。
   - 输出：小红书 / 朋友圈 / 公众号三版成稿与同型号配图，一键复制、一键下载图片。
   - 秒级、零模型成本、零幻觉；模型服务不可用时也能交差。
2. **极简模式（已有）**：模型引导追问，适合想多写几句的店员。
3. **专业模式（已有）**：总部或运营人员精修重点推文。

快发稿可一键"交给 AI 润色"：模型只许改表达，事实槽位锁定不变。

## 三、快发模式的设计

### 3.1 事实卡（从 P1 自动生成，人工确认）
- 解析 `P1-产品参数库/*/产品事实.md`。格式统一为"章节 / 字段名 / 值"，并带 `*` 开头的限定说明。
- 每款输出结构化卡片：`{字段, 值, 版本差异, 限定条件, 来源 URL}`，例如重量按标准屏 / 典藏版分列。
- **带限定条件的值必须连同条件一起使用**，例如"峰值亮度 1600 尼特"要附 HDR 条件；没有条件的场合不使用该字段。
- 存为 `facts/<型号>.json`，作为模板与模型共用的唯一事实来源。新品上市时总部只需维护这一份。

### 3.2 句库（总部审核一次，长期复用）
- 片段类型：开头钩子、场景描写、卖点句（带事实槽位）、门店到访引导、结尾互动、话题标签。
- 按 **人群**（学生 / 教师 / 商务差旅 / 内容创作 / 管理者 / 企业采购 / 旧机换新）× **平台** 分组。初稿从 P2 按型号角色沟通卡、P8 客户场景库提炼。
- 卖点句写成 `重量仅 {重量}，通勤包里不占地方`。所需事实缺失时，整句不可用，而不是留空或编造。

### 3.3 组合与去重
- 按人群、平台筛选片段，加权随机组合；同一门店近 N 次用过的片段降权。
- 门店真实见闻插入固定位置，作为开头或场景段，是不同门店内容差异的主要来源。
- 输出前计算与本店近期稿件的相似度，超过阈值就换片段重组。

### 3.4 安全闸（复用现有规则）
- 复用 `policy.text_violations`：拦截价格、补贴、绝对化用语、虚构亲测。
- 店员输入的见闻同样过一遍闸，例如"全网最低"直接提示修改。

## 四、AI 模式的提升（极简 / 专业 / 润色共用）

1. **数字锁定**：模型只写 `{F3}` 这类占位符，由程序填入核验原值并校验没有改动。实现前先确认现有 `agent.py` 的做法。
2. **去 AI 味**：禁用套话清单（"在这个快节奏的时代""赋能""小伙伴们""不仅……更……"等）；要求句长有变化、至少一个具体细节；超标则重写一次。
3. **资料没有就不写**，转为"到店体验"引导。
4. **总部统一配置模型**：部署者用环境变量提供模型，店员界面隐藏 API 设置；保留会话内覆盖，供开发与评测使用。

## 五、体验要求

- 手机竖屏优先：快发模式单列布局，大按钮，三平台用标签页切换。
- 首页默认进入快发模式；极简 / 专业作为"更多方式"。
- 店员全程不出现 API、知识库、风格卡等术语。

## 六、实施计划

| 阶段 | 内容 | 产出 / 验收 |
| --- | --- | --- |
| P0 事实卡 | P1 解析器、限定条件处理、10 款型号事实卡、单元测试 | 10 款卡片字段正确；带条件的值不会脱离条件 |
| P1 快发原型 | 句库初稿（朋友圈 + 小红书，3 类人群）、组合器、安全闸、最简界面 | 同型号 3 家门店输入不同见闻，生成 3 篇明显不同且无违规的稿件 |
| P2 补全 | 公众号模板、7 类人群、门店档案、去重、配图打包、移动端样式 | 手机上 30 秒完成一次任务（录屏计时） |
| P3 AI 提升 | 数字锁定、去 AI 味规则、润色入口、总部统一模型配置 | 真实模型样稿评测：数字零改动，套话命中率下降 |
| P4 视频素材 | 真实模型样稿、对比实验、拦截演示、架构图 | 视频所需录屏与截图齐全 |

P0 与 P1 是最小可演示闭环，优先完成；P3 可与 P2 并行。

## 七、视频脚本（3–5 分钟）

1. **痛点开场**：店员下班前还要交三篇推文；展示几家店发出的雷同推文。
2. **傻瓜式演示**：手机实录，选型号、说一句见闻，几秒拿到三平台成稿并复制发布。
3. **不重样**：三家门店同一新品，三篇不同的成稿并排对比。
4. **不出错**：点开任意数字看到官方原文与条件；故意要求"写最低价、说最强"，现场被拦截。
5. **两档能力**：日常用快发（零成本、秒出），重点推文用 AI 精修，同一套事实。
6. **一页架构**：事实层 / 表达层分离；新品只需更新一份事实卡，全国门店当天可用。

## 八、风险与待确认

- 句库质量决定快发模式的上限，需要团队成员参考真实小红书高互动笔记来写，并请熟悉业务的人审一遍。
- P2 / P8 资料的用途边界需确认：只用于提炼表达和场景，不作为产品事实来源；P4 价格政策库（机密）不使用。
- 真实模型的生成质量和耗时尚未系统评测，P3 前需先跑一批基线样稿。
- 平台对相似内容的限流规则未核实；去重阈值靠经验设定。
- 复赛截止时间和团队分工待定，阶段排期据此调整。
