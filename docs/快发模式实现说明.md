# 知衡 · 快发模式实现说明

快发模式（2026-10-20 起）是复赛规划里的默认入口：**不调用模型**，店员选型号 + 写一句门店真实见闻，
几秒拿到小红书 / 门店朋友圈 / 微信公众号三版成稿，每个数字都能点开看到官方原文与限定条件。

数据流：

```
P1-产品参数库/<分类>/<型号>/产品事实.md
        │  tools/build_facts.py（离线，人工复核）
        ▼
facts/<型号>.json  事实卡（唯一事实来源）
        │
sentence_library.py 句库片段 ──► quick_flow.py 组合器 ──► policy 安全闸 ──► 三平台成稿
        │                              │
        │                              └─ .local/quick-history/<门店哈希>.json（去重历史）
        ▼
quick_ui.py 快发界面（studio_ui.py 里是第三档模式）
```

## 1. 事实卡（P0）

构建命令（改完知识库或解析器后重跑）：

```powershell
cd C:\Users\14611\Projects\zhekesong-huawei-2026
$env:PYTHONIOENCODING='utf-8'
# 仓库里只提交笔记本类目（句库是照笔记本写的；手机/穿戴等扩品类时再加 --categories）
.\.venv\Scripts\python.exe tools\build_facts.py --categories '鸿蒙电脑,笔记本,MateBook'
.\.venv\Scripts\python.exe tools\build_facts.py --check      # 只校验不写
.\.venv\Scripts\python.exe tools\build_facts.py              # 全品类（不提交，供调试）
```

- 来源：`knowledge_store.WORKSPACE_SOURCES` 里的授权知识库，**先出现的库赢同名型号**
  （`任德耀新建华为PC知识库/华为PC全板块深度知识库_v7` 优先，`华为官方产品库_v1` 补手机/穿戴/笔记本）。
  当前 `facts/` 是 11 款笔记本（10 款 PC 库 + 1 款官方库独有 SKU），约 190 KB。
- 卡片字段：`model / folder / category / library / captured / urls / positioning / selling_titles / fields[]`。
  每个 field 是 `{section, name, values[], conditions[], quote}`，每个 value 是
  `{text, variant, inline, label, conditions}`；`quote` 是它自己那几行官方原文，供人工核对。
- 槽位词表在 `facts.SLOT_ALIASES`（19 个：重量 / 厚度 / 屏幕尺寸 / 屏幕类型 / 分辨率 / 刷新率 /
  屏占比 / 电池 / 充电 / 处理器 / 操作系统 / 存储 / 内存 / 摄像头 / 前置摄像头 / 防尘抗水 / 接口 / 蓝牙 / 星闪）。
  `facts.resolve(card, slot)` **只认词表内的槽位**，模板拿不到任意字段。其中 `接口` 是**汇总摘要**
  （把 `左侧：HDMI2.1…USB-C × 1…` 收敛成 `USB-C、USB-A、HDMI`，≤24 字），避免整段端口清单进正文。
- 限定条件三条规矩：
  1. 行内括号条件（`约 1.33 kg（圆键盘含电池）`）随值一起渲染，`display()` 负责补回括号；
  2. `*` 开头的限定说明进 `conditions`，界面「这篇用到的数字与官方原文」里逐条展示；
  3. 源文件没写条件的，解析器不自己造条件（缺就是缺，模板整句停用）。
- 质量闸（宁缺勿错）：
  - `厚度` 超过 50 mm 判为物理量错位，直接停用该槽位；
  - `接口` 不提供槽位（端口清单读不成句）；
  - `摄像头` 优先取「后置」，`操作系统` 优先 Windows / HarmonyOS；
  - `tools/build_facts.py` 的 `report.warnings` 会列出「屏幕尺寸缺圆角说明」「值里残留脚注星号」
    「厚度超出合理范围已停用」等问题，出卡后先看这一段。

已知源数据问题（属于 P1 采集，不该由解析器猜）：

| 问题 | 影响 | 处置 |
| --- | --- | --- |
| 4 张 Windows 卡把 `长度` 当厚度、`厚度` 当深度（MateBook D 14 / D 16 / D 16 SE / X Pro） | 厚度槽位不可用 | 解析器按量纲判为可疑后停用，等源文件修正 |
| 7 张卡的屏幕尺寸段没有「圆角设计 / 标准矩形」说明 | 屏幕尺寸无条件下发 | 记入 warnings，补采后再放开 |
| 部分卡把两个 SKU 写在同一段（MateBook D 14） | 同名字段被合并去重 | 解析时合并多值，不再「后者覆盖前者」 |

## 2. 句库（`sentence_library.py`）

- 片段类型 `KINDS = hook / scene / benefit / evidence / store / ending / tag`；
- 片段结构 `{id, kind, text, slots, audiences, platforms, weight}`；`text` 里用 `{槽位}`；
- `fragments(kind, audience, platform)` 过滤：`audiences` / `platforms` 为空表示通用；
- `validate()` 自检：槽位是否在词表内、有没有阿拉伯数字、是否命中 `policy.BANNED` / `policy.DYNAMIC`、
  是否命中禁用套话、长度上限、各 kind/人群的数量底线。**改句库后必须跑一次，返回空列表才算通过。**

新增片段的约定：一个片段尽量只用 1 个槽位；值自带单位，模板不要再补单位；不要把字段名紧贴槽位写
（`存储{存储}` → 出稿会变成「存储512 GB」，要写成「机身存储给到{存储}」或直接省略字段名）。

## 3. 组合器（`quick_flow.py`）

- 品类限制：`quick_flow.models()` 只列笔记本类目（`鸿蒙电脑 / 笔记本 / MateBook`），`generate()` 也会拒绝
  其他品类的卡片——句库是照笔记本角色写的，手机/手表套进去会出「塞进电脑包」这类硬伤。其他品类走极简/专业模式。
- 配额：`PLANS` 决定每个平台先用哪些 kind、各几条；不足目标字数时按 `benefit → evidence → scene → ending`
  继续补，超过上限则从尾部删可选片段。
- **槽位去重**：同一篇里一个槽位只用一次，重复的片段会被跳过（避免同一重量说两遍）。
- 见闻置顶：店员那句真实见闻固定作为开头，是不同门店内容差异的主要来源。
- 长度：直接读 `policy.PLATFORM_RULES[platform]["body_target"]`（小红书 350-650、朋友圈 80-180、公众号 650-1000）。
- 去重：历史存 `.local/quick-history/<门店哈希>.json`；近 12 个片段降权（×0.2），
  与近 4 篇成稿算字符 3-gram Jaccard，超过 `SIMILARITY_LIMIT = 0.62` 就换片段重组，最多 5 次。
- 安全闸：`policy.text_violations(text, facts, product)`，数字必须能在用到的卡片引文里找到；
  见闻先过 `check_visit()`（价格、补贴、绝对化用语、虚构亲测直接拦下并提示改）。

### 3.1 配图（按平台）

- 图源：型号目录下的 `images/`；配图说明与来源页读同目录的 `图片索引.csv`（`文件名 / 官网图片说明 / 建议用途 / 来源页面`）。
  文件名里的画面主题（如 `…_高清护眼屏幕_05_…jpg`）优先当标题，官网说明常常只是型号名。
- 张数直接取 `policy.PLATFORM_RULES[platform]` 的 `image_min / image_max`：小红书 3-6、门店朋友圈 1-3、微信公众号 2-4；
  源图不足时按实际张数给，界面标注「官方图不够，可补门店实拍」。
- 三个平台不端同一组图：同一次生成里别的平台用过的图降权，各平台再按用途关键词（配色 / 外观 / 场景 / 细节）优先挑。
- 图片**不进事实卡**（体积大、有版权、仓库里也不提交源图），运行时按卡片里的 `library / category / folder`
  回源目录读；源目录不在本机时返回空列表并说明原因，绝不凭空造图。
- 「打包三平台配图与文案 ZIP」把三份文案 + 各自配图按平台分文件夹打成素材包，附 `文案.txt` 记录每张图的用法与来源页。

## 4. 界面（`quick_ui.py`）

- 入口：`studio_ui.py` 首页三张卡片，快发排第一；进入后不显示「资料来源」面板（快发不读 ima、不配模型）。
- 输入：型号（只列出有事实卡的型号）、人群、一句见闻、门店档案（`gr.BrowserState` 存在浏览器里，只用于结尾到店引导）。
  - **见闻预选卡**：`quick_flow.VISIT_PRESETS` 里 11 个常见门店场景（老师问投屏、学生问宿舍、家长问网课、出差问续航、
    开会要轻、剪视频问颜色、接口接投影、旧机换新、老人怕不会用、采购问批量、负责人问资料）。点一下**同时填好见闻和人群**，
    店员可以接着改；文案本身过 `check_visit()` 安全闸，不含价格、优惠、绝对化说法和虚构亲测。
- 输出：三平台标签页，各自「成稿 + 状态（字数 / 相似度 / 检查结果）+ 同型号官方配图 + 配图用法与来源 + 事实依据」，
  一键复制，「换一批」重组；底部「打包三平台配图与文案 ZIP」出素材包。
