# 手输型号与资料溯源（极简 / 专业模式）

两种模式的产品字段都允许自由输入（`allow_custom_value=True`）。用户不必记得目录里的完整写法：
输入「matebook d 14 2024」后离开输入框，系统会把它匹配到目录里的准确型号并回填；
拿不准时只给候选，绝不替用户挑。

## 1. 匹配规则（`product_match.py` + `policy.resolve_product`）

1. **归一化**：NFKC（全角/半角）、转小写、去掉「华为/HUAWEI」前缀、去掉空格/括号/横杠等分隔符。
   所以 `HUAWEI MateBook 14（鸿蒙版）`、`matebook14鸿蒙版`、`华为 MateBook 14(鸿蒙版)` 等价。
2. **硬约束**：型号家族、年份、操作系统（鸿蒙/Windows）对不上直接判不匹配，分数归零。
3. **打分**：字面相似度（difflib）+ 型号要素加分（系列 +0.22、尺寸 +0.10、年份 +0.06、SE/Pro S/Ultra +0.04、系统 +0.03）。
   最终 `>0.92` 且领先第二名 `>0.06` 才算唯一命中。
4. **保守自动补全**（`_auto_match_allowed`）——「宁可多问一句」：
   - 用户写了系统（鸿蒙版/Windows）而候选没写系统 → 不猜；
   - 候选带年份而用户没写年份 → **一律追问**（年份决定资料归属，不能因为目录里只有一个就替用户认定）；
   - 候选带 SE / Pro S / Ultra 而用户没写时，只有目录里唯一对应才允许补全；
   - 完全相等（归一化后）始终直接命中。
5. **别名折算**：事实卡里的机型名（如 `HUAWEI MateBook D 14 2024`）与知识库目录名（如 `HUAWEI MateBook D 14`）
   可能不同。`policy.resolve_product` 先用事实卡名参与匹配，再把命中的别名折算回**目录标题**，
   保证后续检索用的一定是知识库认识的写法。

匹配结果三态：`matched`（回填并显示「✓ 已匹配到…」）、`ambiguous`（列出前 3 个候选，让用户选）、
`unknown`（目录里没有相近型号，提示补全型号或提供官方商城商品页链接）。

## 2. 生成时的资料获取与“来源准确”边界

- **数据库优先**：命中型号后走 `IMAClient.retrieve()`，只读该型号在知识库/归档里的正文与图片；
  检索返回的型号必须与任务型号一致，否则停止生成（`### 型号核对未通过`）。
- **官方网页补充**：用户可在「补充要求」里贴华为官方商城商品页链接
  （`https://www.vmall.com/product/数字.html`），`vmall_client` 只读该商品页正文，
  并用标题/型号/年份/系统做同一性校验；不读首页、搜索页、推荐位。
- **无依据就停**：知识库与官方商城都拿不到正文时，返回「没有可用的事实依据」并提示补链接，
  不会用模型记忆或别的型号资料凑数。
- **事实核验不变**：`policy.evidence_facts` 要求每条事实的引文能在来源原文里逐字定位；
  动态价格/权益、营销案例不作为产品事实。

## 3. 界面入口

- 专业模式：第 1 步「产品型号」下方有匹配提示（`#zh-product-hint`），输入后失焦自动匹配。
- 极简模式：「产品类型」下方同款提示（`#zh-simple-product-hint`），同样失焦匹配。
- 生成时 `policy.validate_inputs` 会再解析一次（服务端兜底），因此直接调用 API 也享受同样的匹配与拦截。

## 4. 测试

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_product_match -v   # 匹配器 42 项（含真实目录审计）
.\.venv\Scripts\python.exe -m unittest tests.test_policy -v           # 输入策略（含别名折算）
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
```

真实目录审计（11 个型号 × 3 种简写 = 33 条）：33/33 通过，其中 5 条是「安全歧义」
（未唯一命中，但候选里含正确型号，交给用户确认），0 条无提示或误匹配。

## 5. 已知限制

- `matebook 14 ultra`：与「14（鸿蒙版）」都饱和到 1.0 并列，返回歧义而非唯一命中（保守可接受）。
- `MateBook 99`：不存在的数字仍会给出相近候选（ambiguous），不会直接判 unknown。
- 同时写「鸿蒙版」和 windows：当前按鸿蒙优先匹配，没有提示冲突。
- 目录写法与事实卡写法差异较大时依赖别名表；事实卡没覆盖的型号只能手工写目录里的名字。
